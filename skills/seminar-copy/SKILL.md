# seminar-copy — セミナー告知コピー生成

知識の出典: `01_Knowledges/03_Web_Knowledge/セミナー告知コピーは対象者→結果→証拠→CTAの順で書く.md`
（X Business公式 / LINE公式コラム / Eventbrite / ON24 / Unbounce / AZKK A/Bテスト事例に基づく）

## 大原則

申込が増えるコピーは「うまい文章」ではなく、**誰向けか・何が得られるか・今動く理由・どう申し込むか**が一瞬で伝わる文章。

- **X = 興味喚起の場**（スクロールを止め「自分に関係ある」と思わせる）
- **LINE公式 = 刈り取りの場**（不安を消し、迷わせず申し込ませる）

コピーの並びは必ずこの順: **対象者 → 悩み/課題 → 得られる結果 → 証拠 → 開催情報 → CTA**

## Step 1: 入力の確認

以下をユーザーの発言から抽出する。**推定できるものは聞かない**。不明で致命的なものだけ質問（最大2つ）。

| 項目 | 必須 | 例 |
|---|---|---|
| テーマ・内容 | ◎ | 訪問リハ職向けAI活用 |
| 対象者（絞る） | ◎ | 新人PT / 院長 / 記録が終わらない人 |
| 得られる結果（〜3つ） | ◎ | 記録30分短縮の手順、明日から使えるプロンプト |
| 日時・形式 | ◎ | 7/25(土)20:00 Zoom |
| 価格 | ◎ | 無料 / 3,000円 |
| 限定性 | ○ | 先着30名 / 今夜締切（なければ提案する） |
| 証拠・実績 | ○ | 累計300名参加 / 有償実績4件（なければ省略） |
| 申込URL | ○ | なければ「[申込URL]」プレースホルダ |

## Step 2: 生成（3点セット）

### ① X投稿 — フック違いで3案

各案とも: 短く・1投稿1メッセージ・数字入り・CTA1つ・ハッシュタグ0〜2個。本文の目安は全角140字以内に収める。

- **A案（対象者訴求）**: 「[対象者]へ。」で始める
- **B案（悩み訴求）**: 「[痛みの一文]な人へ。」で始める
- **C案（結果訴求)**: 「[時間]で[成果]。」で始める

テンプレ:
```
[フック1行]
[得られること（数字入り・最大3つ）]
[日時] / [価格] / [先着・締切]
申込はこちら → [URL]
```

### ② LINE配信文 — 1案＋フック代替案

LINEは即開封（当日中に約8割）なので刈り取りに全振り。箇条書きでスキャン可能に。CTAは露骨でよい（実証: 誘導文言ありCTR 11.1% vs なし8.4%）。

```
[冒頭フック（限定性 or 結果）]

こんな方におすすめ
・[対象1]
・[対象2]
・[対象3]

このセミナーで得られること
・[成果1（数字入り）]
・[成果2]
・[成果3]

📅 [日時] / [形式]
💰 [価格]
⚠️ [先着・締切]

▼申込はこちら（[所要秒数]で完了）
[URL]
```

### ③ リッチメッセージ見出し — 4案

10〜13文字・1画像1訴求。画像は1枚完結型を推奨（実証: 1枚 CTR 22.7% vs 2枚 13.8%）。CTAボタンあり画像を推奨（52.2% vs 50.2%）。

例: 「残席わずか」「無料・60分で理解」「明日から使える」「先着30名・今すぐ申込」

## Step 3: セルフチェック（NG検出）

生成後、以下に該当したら書き直してから出す:

- [ ] 「どなたでも歓迎」等、対象が不明 → 対象者を限定
- [ ] 「学びの多い」「充実の内容」等の抽象語 → 数字・具体成果に置換
- [ ] 「ぜひご参加ください」等の弱CTA → 「今すぐ申込」「無料で参加する」
- [ ] 「近日開催」等、日時・締切が曖昧 → 具体日時＋締切/先着
- [ ] CTAが2つ以上 → 1つに絞る
- [ ] X案が長すぎる／訴求が2つ以上 → 削る

## Step 4: A/Bテスト提案

出力の最後に、検証優先順で1行ずつ提案する:
1. フック（対象者 vs 悩み vs 結果）→ 2. CTA文言 → 3. 先着/締切の有無 → 4. 証拠の有無 → 5. 画像1枚 vs 2枚

## Step 5: 効果測定（配信後に評価を頼まれたとき）

ファネルで「どこで落ちたか」を切り分ける。1つの数字でコピーの良し悪しを判断しない。

```
友だち数 → 開封（開封率＝冒頭1行目の責任） → クリック（CTR＝本文/CTAの責任） → 申込（CVR＝LP/価格の責任）
```

| 指標 | 悪い | 普通 | 良い | 見る場所 |
|---|---|---|---|---|
| 開封率 | 〜40% | 50〜60% | 65%〜 | LINE公式インサイト |
| CTR（対開封） | 〜5% | 8〜15% | 20%〜 | 同上（テキストURLはチャネル別リンクで計測） |
| CVR（申込÷クリック） | 〜3% | 5〜10% | 15%〜 | 申込プラットフォーム |
| ブロック率 | 1%〜 | 0.3〜0.5% | 〜0.2% | LINE公式インサイト |

判定ロジック: CTR高×申込少 → コピーは妥当、LP/価格が原因。CTR低 → 本文/CTAを改善。開封率低 → 冒頭1行目を改善。

### 計測の事前準備（配信前に必ず提案する）

- チャネル別リンク（LINE用/X用でUTMまたは短縮URLを分ける）。これがないと成果の帰属が不明になる
- 申込フォームに「どこで知りましたか」を1問
- 配信ログを1配信1行で記録: 日付/フック型/CTA文言/開封率/CTR/申込数/ブロック数

### 小規模リストの注意

友だち数が数百以下なら同時A/Bは統計的に無意味。「1配信1変更」の逐次比較＋定性シグナル（返信・言及）で評価し、判断単位は1配信でなく1キャンペーン（告知→前日→当日の合計申込数）にする。外部基準値より自分の過去配信との比較を正とする。1回目はベースライン取得と割り切る。

### 評価タイミング

配信24時間後（開封/CTR確定）→ 締切後（CVR・チャネル別申込）→ セミナー後（参加率・アーカイブ視聴率）

## ルール

- 【個人事業（Standby）専用のトーン】スピード感・実務感を優先。ただし本業案件で呼ばれた場合は組織トーンに調整
- 限定性が本当にない場合、嘘の「先着」は書かない。代わりに締切（申込フォーム閉鎖日）の設定を提案する
- SNS戦略全般の相談に発展したら `sns-marketer` エージェントに引き継ぐ
