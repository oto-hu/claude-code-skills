学び資産の保存場所: `/Users/you/Documents/Obsidian Vault/01_Knowledges/`

## 分類の定義

| 軸 | 値 | 意味 |

| knowledge_type | 前景 | 明日から使える実践知（手順・パターン・判断基準・数字） |
| knowledge_type | 背景 | 判断の土台になる文脈・原理・教養 |
| source_type | experience / web / book / paper / seminar | 学びの出どころ |

## 記録モード（「学んだ」「学びメモ」「/learn ○○」）

1. ユーザーの発言から「学びの核心・出どころ・前景/背景」を読み取る。不明な点だけ短く質問（最大2つ。推定できるなら聞かない）
2. テンプレートに沿ってノート作成。**ファイル名＝学びを一文で**（例:「iCloudにコードを置かない.md」）。1学び1ノート
3. frontmatterの `apply_to` に効く事業（本業 / standby）を入れる
4. `INDEX.md` の該当セクション（前景/背景）に1行追記:
   `- [[ノート名]] (source_type/日付) — 一言要約 #適用先`
5. 関連する既存ノートがあれば `[[リンク]]` で相互接続

## 参照モード（「学びを踏まえて」「過去の学び」）

1. `INDEX.md` を読む（全学びの一覧が1行ずつある）
2. 関連しそうな行のノート本体を開いて内容を反映
3. INDEXにない話題はGrepで `01_Knowledges/` を検索
4. 回答に使った学びは `[[ノート名]]` で明示する

## 差分モード（「これが実際に出した版」「投稿した完成版」＋URL/最終稿）

**このスキルで最も効く部分。** 草稿に手を入れた差分こそがYouらしさで、放っておくとどこにも残らない。
AIは自分の原稿がどう直されたか知らないまま、次も同じ書き方をしてくる。

対象：note記事・X投稿・提案書・スライド・メール・LP文言など、**AIが草稿を書いて人間が直して世に出したもの全て**。

1. AIが出した元の草稿を特定する（同一セッション内にあればそれを使う。無ければ「元の草稿はどれか」を1回だけ聞く）
2. 完成版を取得する（URLならWebFetch、ファイルなら読む）
3. 元と完成版を突き合わせ、次の4点に分けて差分を出す
   - **削られたもの**（何が冗長・不要と判断されたか）
   - **足されたもの**（AIが持っていなかった情報・体験・具体例）
   - **言い換えられたもの**（語彙・語尾・リズムの癖）
   - **順序が変わったもの**（何を先に出すか＝優先順位の癖）
4. 差分の**理由を1つずつ言語化**する。「削った」ではなく「なぜ削られたか」まで書く
5. `01_Knowledges/01_My_Knowledge/` に文体・判断基準の学びとしてノート化（既存ノートがあれば追記）
6. 反響データ（PV・スキ・クリック）が手元にあれば、同じノートに結果として併記する

**この差分は必ず記録する。** 記録しなければ次回も同じ直しをすることになる。

## ルール

- 記事の丸写しはしない。**Youの言葉で要約**したものだけがノートになる（原文クリップは `Clippings/` が一時受け、整理後の保管先は `03_Materials/01_Clippings/` のトピック別サブフォルダ）
- 提案・設計・事業判断の際、関連する学びがINDEXにあれば**言われなくても参照**してよい
- 同じ学びが既にあれば新規作成せず追記・更新する
- **差分は推測で書かない。** 元の草稿が特定できないときは差分モードを実行せず、その旨を伝える
