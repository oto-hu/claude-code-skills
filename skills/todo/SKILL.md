# TODOキュー処理

## 前提情報

**個人事業のタスクの正は Notion のタスクDB。**（2026-08-03決定。カレンダーの `[TODO]` 終日イベント運用は廃止した）
本業は稼働が少なくタスク管理の対象外。カレンダーの本業予定は空き時間の算出にだけ使う。

- **タスクDB**: database_id `00000000-0000-0000-0000-000000000000` / data_source_id `00000000-0000-0000-0000-000000000000`
  - プロパティ: タスク名(title)・事業(select: Standby Post/Standby Tech/その他個人事業/新規事業)・ボール(select: 自分/Claude/待ち)・ステータス(select: 未着手/進行中/完了)・期限(date)・メモ(rich_text)
- **個人事業カレンダー（プライマリ）**: `you@example.com`
- **本業カレンダー（本業スケジュール）**: `work-calendar-id@group.calendar.google.com`

## 実行ステップ

1. **TODOキューの取得**
   - Notion MCP の `query-data-sources`（SQLモード）でタスクDBの `ステータス != '完了'` を取得
   - 「ボール」で仕分ける：`自分`＝実行対象／`Claude`＝自動処理候補／`待ち`＝相手待ちなので今日の枠には入れない
   - 期限なしのタスクは落とさず「期限なし・自分ボール」として必ず列挙する（放置されやすいため）

2. **今日のスケジューリング**
   - 両カレンダーの今日の予定を取得し、空き時間ブロックを算出
   - 9:00〜19:00 を作業可能時間とする（**現在時刻より後の枠だけ**割り当てる）
   - 期限が近い順に割り当てる。所要時間はメモから推定できなければ 30min〜1h で仮置きし、仮であることを明記する
   - 依存関係（「〇〇の後に着手」と書かれたタスク）を守り、詰まると連鎖する上流タスクを優先する

3. **自動処理（ボール＝`Claude` のもの）**
   - コード修正・記事下書き・調査・n8nワークフロー作成など、Claude単独で完結するものを実行する
   - 成果物は**フルパス（絶対パス）**で報告
   - 送信・支払い・git push・コミットは承認待ちにする（実行しない）

4. **完了処理の提案**
   - 完了したタスクは Notion のステータスを `完了` へ更新することを提案し、**承認後に**書き込む
   - 書き込みは公式APIスクリプト経由。token: `/Users/you/projects/standby/case-management-package/.env` の `NOTION_TOKEN`、実行: 同プロジェクトの `.venv/bin/python`
   - notion-client 3.1.0（新API）：ページ作成は `parent={"type":"data_source_id","data_source_id":...}`
